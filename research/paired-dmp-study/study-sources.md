## Publication, matrix, and software are distinct

- [Mansour et al., Zenodo 19630859](https://zenodo.org/records/19630859) is an openly accessible **preprint**, v1, published 2026-04-17, licensed CC BY 4.0. Its 28-page [PDF](https://zenodo.org/records/19630859/files/DMP_Evaluation_V1.0.pdf?download=1) contains the lifecycle framework, Table 2 criteria matrix, discipline guidance and tool tutorial. The matrix is part of this publication, not a separate empirical validation paper.
- Table 2, printed pp. 6–21, covers six areas: data collection; documentation/quality; storage/backup/security; legal/ethical requirements; sharing/preservation; responsibilities/resources. There are 16 subsections: 1a–b, 2a–b, 3a–c, 4a–c, 5a–d, 6a–b. The mid-project cell of 5d is blank. Section 4a explicitly allows an inapplicability statement when personal-data requirements do not apply.
- Section 3 distinguishes planned approaches, implementation/progress, and completed outcomes. It defines no numerical project-duration cutoffs. The user confirmed early ≤50% and late >100% of project duration, calculated from **documented DMP issue dates**; publication/deposit dates provide supporting evidence. These are study sampling rules, not the publication's definition of early/end stage.
- Section 4 links materials and plant guidance. The attached DOCX files were not read; six-discipline guidance cannot be assumed.

The PDF's implementation links resolve to [Zenodo 19486055](https://zenodo.org/records/19486055), **software**, not another scientific paper: `usadellab/dmp-eva: v0.1`, archived 2026-04-09, MIT licensed. Its only file is a source ZIP. The tag resolves to commit [`db85e5a71271239f8fbe3e271e4aa8b7e71d6321`](https://github.com/usadellab/dmp-eva/tree/db85e5a71271239f8fbe3e271e4aa8b7e71d6321), dated 2026-02-23. Do not conflate this release with current main.

The preprint reports no empirical benchmark sample, human-label protocol, inter-rater reliability, comparative model experiment, or validated numerical score mapping. A human reference and study protocol must be specified independently. This is a finding about the inspected preprint, not proof that no other publication exists.

## Study-design recommendations inferred from this review

These are proposed methods, not claims that the sources mandate them:

1. Freeze the published matrix and build an explicit criterion crosswalk to whichever evaluation tool is actually studied; resolve omissions, applicability, evidence units and aggregation before scoring. Treat document sufficiency separately from independent verification that a project performed the reported actions.
2. Keep metadata-only selection locked before reviewers see quality judgments. After verifying same-project, same-scope pairs, apply the confirmed early ≤50% / late >100% rule to documented DMP issue dates, with publication/deposit dates retained as supporting evidence. Record documentary context and issue-date uncertainty; a later repository deposit alone does not establish late eligibility.
3. Use two independent human reviewers, blinded to AI outputs, with evidence locations, applicability reasons and a predefined adjudication procedure. Pilot and clarify the rubric outside the final evaluation set when feasible; retain initial and adjudicated ratings. Avoid claiming a validated 0–100 gold standard merely because the app emits numbers.
4. Freeze the canonical extracted text for every document and inspect tables, annexes and completeness. Never make a full-document claim from truncated input. Treat native JSON versus normalized text as a separate input-format experiment.
5. Prepare a frozen DMP-EVA baseline against human assessments for subsequent model-backend comparisons in Mainz. Compare models under the same rubric, prompt and extraction first; compare prompts under the same model separately. Pre-register repeated runs and record exact request/response, snapshot/commit, model identifier, parameters actually sent, hashes, errors and timing. Do not tune prompts against all 12 reference judgments and call the same set a held-out evaluation.
6. Report criterion-level agreement, omissions/unsupported claims, runtime failures and variability, alongside any aggregate. Treat six projects as a small paired case study, not population evidence for six disciplines; multiple criteria and repeats do not create independent projects.
