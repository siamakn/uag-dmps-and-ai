The human pilot remains deferred; formal reviewers are unassigned. Preparation can continue now. ## Question, cohort and units

How does pinned DMP-EVA behave in its native configuration, and, separately, does criterion-at-a-time assessment agree more closely with independent human assessments than whole-rubric assessment at a fixed model and fixed information exposure? Later model comparisons hold the chosen prompt and input constant. Native versus configured results describe an intervention package; they cannot isolate the effect of a single fix.

Use the proposed six same-scope project pairs in [cohort-proposal.json](cohort-proposal.json): iMagine, EGI-ACE, NANOFACTS, AGRICORE, SUSTRACK and RECHARGE, one documented discipline slot each, twelve documents. Eligibility uses documented issue dates at ≤50% and strictly >100% of duration against the latest authoritative end, retaining alternative dates/extensions and secondary/tied memberships. [Pair review](pair-review.md) supports provenance and eligibility, not DMP quality. Cohort freeze is pending; selection must not respond to human/model scores, text quality, successful model execution or desired effects. Input problems are reported, rather than dropping difficult documents after seeing results. AGRICORE's submission terms remain unresolved; public access alone does not authorize external model submission.

The independent sampling/analysis units are **six project clusters**. Documents, criteria, evidence units and repeated generations are nested observations. One project per discipline supports case description, not discipline rankings or population accuracy. The early/late contrast is observational: phase expectations, document length, project context and time change together. It is not a causal estimate of DMP improvement.

## Proposed staged matrix

All model IDs/endpoints are **unassigned**. `M0` means one exact eligible model/version selected later from Mainz availability, not a currently recommended model. `M1` is a later alternative. Each document is assessed independently, without its paired version or previous model conversation. Archive scheduled randomized/counterbalanced run order; interleave paired conditions so backend changes or time of day do not align with one condition. Record actual execution order and service revisions.

| Condition | Input and rubric | Task/output | Purpose |
| --- | --- | --- | --- |
| N0 native diagnostic | Reviewed common TXT passed through unchanged native parser; default 14-ID rubric/prompt, actual single-run phase behavior | Native evidence-unit 0–100 and native aggregates, unchanged | As-is operational baseline against full-packet reference, with input/phase/instrument limitations exposed |
| F0 configured overall | Entire frozen canonical text; explicit complete defined phase cells/anchors, declared phase; fresh versioned configuration/adapter | All defined framework criteria in one request; per-ID 0/1/2 or separate non-score disposition, evidence/rationale | Configured main comparator; “overall” means whole-rubric joint assessment, not one unvalidated global number |
| F1 configured criterion | Exactly F0 text, rubric/anchors, model and settings; one target ID per request, common full rubric context | One criterion per request using the same response fields and scale as F0 | Main prompt/task decomposition contrast; changes target scope/call structure, not model or document exposure |
| M1 extension | Exactly F0 input/prompt/schema/settings where supported; only exact backend/model changes | F0 task | Later model contrast; report unavoidable provider-setting differences |

F0/F1 are **interventions**, not repaired native scores. Full input cannot be assumed to work through current native limits. Before any such run, identify/hash and preflight the exact supported configuration or explicit adapter/code change, context checks and capture path. Native N0 versus F0 changes information, rubric, phase handling and scale jointly; label that comparison operational, with no single-factor attribution. Within F0/F1, rubric context and instructions remain byte-identical except the target-task scope/output cardinality. Do not compare N0 to a full-rubric condition and name the difference a model effect.

Start with local no-model validation, then, only when execution is authorized and terms/configuration are resolved, an outside-cohort technical smoke stage: two documents × N0, F0 and one selected F1 criterion = **6 planned logical requests** at M0, R=1. It tests input transport/schema/evidence locators, not accuracy or all-criterion coverage. It is not happening now.

Proposed first benchmark stage uses M0 and **R=1** for every main condition: N0 12 requests + F0 12 + F1 `sum(K_d)` requests, where `K_d` is the number of defined target criteria for document d (maximum 16, with undefined cells retained as dispositions without a scoring request). Thus `R × [24 + sum(K_d)]`, at most **216 logical requests**. One run per cell cannot estimate stochastic stability. Optional M1/F0 adds `12R` (maximum first-stage total **228**, excluding smoke). Do not start a full models × prompts × phases sweep.

If resources and the frozen protocol later support R=3 for all main cells, total main requests are at most **648** (432 additional over R=1); optional M1/F0 adds 36 for 684. Repeats remain within-document observations. R=3 is a proposed stability extension, not an approved commitment. Freeze R before outputs; do not stop because scores look favorable. Retry attempts add transport calls and are counted separately. Human workload is separately 12 documents × 2 reviewers = 24 assessments (up to 384 criterion rows including non-score dispositions), plus adjudication; it does not create 384 independent cases.

## Inputs, provenance and failure handling

Freeze source PDF bytes, canonical full extraction and version, page/section/offset mapping, QA disposition, annex policy and every transformation. [Extraction QA](extraction-qa.md) examined 24 purposively selected pages, not the complete corpus; neither current text representation is ready to freeze. N0's parser prefix and actual quote-substituted submitted prompt get their own hashes and retained/omitted ranges. F0/F1 must receive identical complete content and the same frozen evidence locators. Full-human versus native-prefix comparison has an information confound. A future matched-prefix human sensitivity assessment requires separate records and a memory-leakage plan; it is optional, not the full-document gold standard.

Prefer a verified single full-context submission for F0/F1. Check the complete assembled request, reserved output and provider overhead with the actual backend tokenizer/context limit; characters/4 and model-name assumptions are insufficient. Page-marked text/chunks are preparation candidates and bounding-box data an audit sidecar, not approved benchmark inputs. F1 must not retrieve a different evidence subset per criterion. If limits prevent full input, record a failed/infeasible condition or revise and re-freeze the design before running it. **Do not automatically average/max/vote scores across chunks.** Chunking needs a separately approved evidence retrieval, deduplication, cross-chunk linkage, omission and final judgment policy; scores from overlapping chunks are not independent evidence.

Each run record must contain condition/document/project IDs; code/config/dependency/rubric/prompt/output-schema hashes; canonical/parser/submitted input hashes; intended/effective phases; endpoint identity (no secrets), exact model ID and returned revision; actual request body with credentials removed; raw response/stream, provider request ID, finish reason, parser status, evidence assignments, native processed output, timing, token usage and retries. Record settings **actually sent**, provider acceptance/unsupported fields and known defaults. A UI temperature or requested seed is not an effective setting; unsupported seeds stay null. Repeats use fresh sessions with the same actual settings, with seeds only when supported and predeclared. Deterministic claims require evidence, not temperature-zero labels. Model self-reported confidence is an output to inspect, never correctness evidence or a human reference.

Proposed retry rule: one initial attempt plus at most two retries for documented transient timeout/429/5xx, respecting Retry-After; archive every attempt and stop a document-condition after that cap. Freeze finite timeout/backoff values during endpoint preflight. No retries for a valid but unfavorable answer, refusal, context rejection, malformed/schema-invalid completed output or missing criterion; preserve the failure. A separately versioned repair experiment is possible, never silent replacement. Mark ambiguous post-submission timeouts/possible duplicate generation; retries do not become planned stochastic repeats. Preserve partial output and distinguish transport, provider/context, refusal, response parse/schema, missing criterion and input/QC/rights failures. No failed run is scored zero or silently removed; report scheduled, attempted, completed and comparable denominators separately. Native internal retry behavior must be inspected/captured before execution and included within the attempt accounting, rather than accidentally multiplying the cap.

## Candidate analysis, to settle before freeze

**Primary estimand candidate:** the difference F1 minus F0 in project-balanced exact disagreement rate against adjudicated human 0/1/2 criterion judgments. For each document compute disagreement proportion on criteria where the human and both conditions have applicable, numeric judgments; average the two document proportions within each project, then equally average six project contrasts. Negative disagreement difference favors F1. This uses ordered labels without assuming equal distance between 0/1/2. It is explicitly conditional agreement, not unconditional accuracy. Choose/freeze the comparable criterion set and zero-denominator handling before labels; a project with no comparable rows remains undefined, not zero.

Pair it mandatorily with applicability disagreement and coverage/missingness on the **fixed human-applicable, instrument-defined denominator**, showing all excluded rows and reason by condition. Do not rank conditions by agreement when differential abstention/failure could explain the result. Give per-project values and denominator counts; criterion microaverages are secondary descriptive summaries. Native N0 keeps its raw 0–100 evidence/category/aggregate outputs: no division by 50, band mapping or human mean-to-100 conversion is approved. A native numerical agreement estimand needs an independently justified/calibrated mapping using outside-cohort material, frozen before final labels/outputs; otherwise report native coverage, evidence correspondence and raw score distributions without claiming ordinal score agreement. Shared-ID comparisons require semantic/phase crosswalk approval.

Report independent human-human exact agreement, ordinal confusion tables, applicability disagreements and adjudication changes before AI-human comparison. Weighted kappa may be a secondary summary only with prespecified weights and degeneracy handling; it cannot replace six project displays or imply independent criterion samples. For R>1 show within-document variation and sensitivity per repeat; summarize within each project before across-project claims. No t-test over criterion rows or repeats, no superiority/power claim from six clusters. Any cluster bootstrap/permutation intervals are explicitly exploratory and fragile at six clusters; no inferential threshold is proposed here.

Describe paired early/late changes only within identical criterion/phase definitions or show the changed expectations explicitly; a higher late score under different anchors is not a common-scale improvement estimate. Keep native aggregation, separately labelled zero-inclusive diagnostics and any future approved human summary distinct. Do not invent one overall human quality score for convenient correlation.
