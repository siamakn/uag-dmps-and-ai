What this is

Every data management plan on Zenodo that could be found by five different queries, joined to CORDIS so each one carries a discipline and a position in its project's life, plus a small registry of study documents found elsewhere.

The paired study (active)

Six EU projects, one per broad EuroSciVoc discipline, each giving two versions of the same DMP: twelve documents in six pairs. Pick a document with the menu in the first column; it lands in that discipline's early or late slot.

  • Timing uses the issue date printed in the document, never the repository publication date. With n = issue date − project start and d = project end − start, in whole days: early is 2n ≤ d (≤ 50 %), late is n > d (strictly after the end). A date exactly at the end is 100 % and is not late. Partial dates stay intervals and are indeterminate when they straddle a threshold.
  • Project end is the latest authoritative date including extensions (D09); a project may fill any discipline it carries in CORDIS, but only one row (D08).
  • Sharing a grant only makes two documents candidates. A pair is verified only when a person has recorded the same scope, that the later document revises the earlier one, the issue dates with page locators, and checksummed files. Until then it is pending; wrong timing, reuse or a contradiction makes it rejected.
  • The lifecycle column below still shows the publication-date position. Treat it as a discovery aid: a delayed deposit cannot make a document late.
  • Served, the draft is saved to data/paired_selection.json; standalone, in this browser under dmpbench.paired.v1. Freeze (served only) checks every file on disk and writes an immutable snapshot to data/paired-snapshots/.

Review (pilot)

The third mode holds the human-review pilot form (PILOT-01: PathOS D3.5 v2.0, criterion 1b, End-Project cell). The pilot is deferred: nothing is needed now and the form stays blank. If someone uses it, the draft is saved as entered, and a submission is checked, confirmed with the reviewer ID, then locked; later changes become a linked correction. Served, it lives in data/review/; standalone, in this browser.

Legacy 3 × 3 selection (historical)

The earlier design picked 10: nine filling a 3 × 3 discipline × lifecycle matrix, plus one challenging case. It stays available under Legacy 3×3, saved in data/selection.json, and confers no eligibility or priority on the paired study.

How the two axes are derived

  • Discipline is the top-level OECD field from the project's EuroSciVoc terms in CORDIS, not a judgement about the DMP. Records with no CORDIS match show no CORDIS match and are hidden as soon as a discipline filter is on.
  • Lifecycle stage is where the publication date falls between the project's CORDIS start and end dates: early up to 34 %, mid up to 70 %, late above. The bar in the column shows the position; positions past the end are printed, not hidden. This legacy label is not the paired study's > 100 % rule.

Reading a row

Click a title to expand the description, project dates, call id and DOI. A green maDMP tag means the record carries a real RDA DMP Common Standard JSON file; schema clean means it has no missing required field, which only 25 of 377 manage. Red tags mark sensitive-data signals — the pool for the challenging case.

Choosing well

Selection is meant to run off metadata, not off how good a plan looks. Filter down to a defensible pool, then take what falls in the cell you still need. The tray warns when two picks come from the same project, when a fourth discipline creeps in, or when a pick has no lifecycle stage.

Where your selection goes

Served locally it is written to data/selection.json on every change. Opened as a standalone file it lives in this browser only. Either way the three Copy buttons put it on the clipboard.
